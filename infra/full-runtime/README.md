# Buffalo Full original application runtime

The container starts upstream `app.js` with Express and WebSocket sharing port 8080. A non-root entrypoint drops inherited capabilities, verifies the Linux launch context, and requires authenticated sessions and bubblewrap. It uses the existing private provider bootstrap only when Workers AI is explicitly configured. Private 3B-8 retains its own image and receipts.

## Native Simlin analysis for a project run

Through the authorized project binding, send `PUT /project/runs/{uuid}/ltm` with the saved model's `revision` and `model_sha256` as a JSON object. Buffalo loads that immutable SD-JSON, converts it with the upstream XMILE converter and runs pysimlin 0.8.5 in the container. The effective integration method defaults to Euler when absent; use the revision's `specs.integrationMethod` and optional `specs.saveStep` to specify another integration or output grid. A successful response is 201, or 204 for the same completed invocation. A different parent on an occupied UUID returns 409. Obtain a new UUID for a new experiment.

Read the trajectory from `GET /project/runs/{uuid}`, the native evidence from `GET /project/runs/{uuid}/ltm` and the SD-AI feedback from `GET /project/runs/{uuid}/feedback`. One transaction saves all three. Native evidence includes signed relative scores on every saved sample, raw link scores where available, partition membership and native periods. The feedback tool carries the full periods and an explicitly sampled score grid of up to 100 instants. Activity classifications cover the full saved grid. A null series denotes unavailable evidence. The source records engine version, installed distribution fingerprint and the evidence hash. Inference has a separate authorization and budget.

A compatible client can reopen an analysis with `openNativeLtmRun(request, runId)` from `native-ltm-client.mjs`. Use the returned model in the new session and pass its `clientRequest` handler the original `feedback_request`, `get_run_info` and `get_variable_data` messages. Send the returned object in the original `tool_call_response`. Merlin's `get_feedback_information` and `generate_ltm_narrative` then consume the selected run.

For server-native runs, Buffalo independently checks each reported dominant coalition against all saved native relative scores in the immutable LTM evidence. It uses the partition and polarity rules of [pysimlin 0.8.5 Run.dominant_periods](https://github.com/bpowers/simlin/blob/40ae5e95f3b9a421405d26eb3cce257b33c19b4f/src/pysimlin/simlin/run.py#L370-L536). A null partition gives each module-internal loop its own timeline. Counts refer to partition–time pairs. Complete matching evidence yields `supported_by_partition_scores`; a conflicting set identifies its partition and first conflicting sample in that partition and blocks narrative generation and storage. Missing scores or partial inventories give `unverified`. Generated prose retains `not_semantically_verified`. This check establishes consistency with native scores on the saved grid; it does not establish agreement with Stella or verify statements in free text.

## Private client integration

Configure a trusted client-facing Worker to use a service binding to the named `FullApplication` entrypoint. That caller must authenticate the user, authorize the project and **overwrite** the `x-buffalo-project` header with its own verified project slug. Each project maps to one Container and SQLite-backed Durable Object. The default public handler returns 404. The private binding preserves original HTTP methods, paths and WebSocket frames. Use the original application authentication key in the REST header or session initialization. The router needs the `APP_AUTH_KEY` secret and an explicitly enabled runtime to start a container.

The project owner can save the exact client-accepted SD-JSON with `PUT /project/model`. Use `If-None-Match: *` to create and the last returned quoted ETag in `If-Match` to update. A stale revision receives 412. `GET /project/model` returns the latest model and ETag even with the container stopped. The current checkpoint limit is 1 MiB. A compatible client can save the accepted model before answering Buffalo's `update_model` request and supply the recovered version in a new `initialize_session`. Model checkpoints do not contain conversation history or tool output.

## Narrate a completed simulation

The returned `assessment` describes two distinct checks. The original engine's prose and loop descriptions carry `prose: "not_semantically_verified"`. Valid identifiers and a nonempty essay can accompany an incorrect statement such as “B1 dominates before year 9.625.”

For complete whole-model score series, the client checks each active sample against its declared dominant group. Scores must sum to 100%, the selected loops must share a polarity and exceed 50%, and a smaller group of that polarity must not already exceed 50%. The result lists the first and last checked samples of each supported period and the signs supplied by the analysis. At a shared boundary the new period owns the sample. A zero initial sample contributes no dominance evidence. A numerical contradiction stops generation and reports the time and group. Missing scores, set-relative denominators, unknown polarity, uncovered samples, non-normalized scores and threshold ties can leave dominance unverified. Clients can display the supported periods beside the original essay. Scores do not independently establish the physical polarity of a causal link. Historical narrative records lacking an assessment have no recorded semantic verification. All new narrative records MUST include an assessment equal to the server-recomputed result, including an explicit unverified dominance status when the evidence is insufficient. Missing, null, incomplete, fabricated or contradictory assessments are rejected with HTTP 422; the server does not infer or backfill an absent assessment. Existing historical records remain readable byte-for-byte and an exact same-ID byte replay returns 204 as an acknowledgement only; a new UUID cannot reuse the historical exception. No migration rewrites legacy data.

The source records the analysis name, version and implementation SHA-256. The content uses SD-AI's feedback loops and dominance periods. Period boundaries and any supplied percentage series use the saved time grid. A shared period retains every dominant loop identifier. The project store authenticates the association with a run. The analysis client is responsible for the scientific origin and accuracy of the supplied values.
