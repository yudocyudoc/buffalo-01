# Buffalo Full original application runtime

The container starts upstream `app.js` with Express and WebSocket sharing port 8080. A non-root entrypoint drops inherited capabilities, verifies the Linux launch context, and requires authenticated sessions and bubblewrap. It uses the existing private provider bootstrap only when Workers AI is explicitly configured. Private 3B-8 retains its own image and receipts.

## Private client integration

Configure a trusted client-facing Worker to use a service binding to the named `FullApplication` entrypoint. That caller must authenticate the user, authorize the project and **overwrite** the `x-buffalo-project` header with its own verified project slug. Each project maps to one Container and SQLite-backed Durable Object. The default public handler returns 404. The private binding preserves original HTTP methods, paths and WebSocket frames. Use the original application authentication key in the REST header or session initialization. The router needs the `APP_AUTH_KEY` secret and an explicitly enabled runtime to start a container.

The project owner can save the exact client-accepted SD-JSON with `PUT /project/model`. Use `If-None-Match: *` to create and the last returned quoted ETag in `If-Match` to update. A stale revision receives 412. `GET /project/model` returns the latest model and ETag even with the container stopped. The current checkpoint limit is 1 MiB. A compatible client can save the accepted model before answering Buffalo's `update_model` request and supply the recovered version in a new `initialize_session`. Model checkpoints do not contain conversation history or tool output.

## Coverage

The build compiles the original Go causal-chains binary and installs production Node dependencies. CI records the catalog reported by the running image, checks the original `predprey` REST generation, and separately selects all five agent configurations in their declared modes using Linux bubblewrap. The image has no Docker daemon, causal-decoder ML stack, Python simulation or visualization environment. A catalog entry alone does not establish that an engine's dependencies or inference path work.

The editing transport passes the original agent's tool schemas and conversation messages to a native Workers AI binding and returns correlated tool calls or final text. This increment admits model reading, granular variable edits and client updates. General engine inference through LLMWrapper, other tool families, and arbitrary provider routes need separate coverage. The template has no AI binding or live limits. An operator must explicitly supply the digest-pinned image, an AI binding named `AI`, a single authorized `AI_PROJECT`, an absolute `AI_EXPIRES_AT` and a cumulative integer `AI_MAX_CALLS` before an inference run. The counter is durable across container restarts. Per invocation limits are 131072 serialized input bytes and 2048 output tokens. Requests that reach the provider consume a reservation even on failure.

The private service binding exposes each reservation by its project-local number, starting at 1, via `GET /project/inference/{number}`. The receipt starts as `RESERVED`. After the binding returns, it includes the observed token counts, neurons, recognized model and finish reason, elapsed time and failed validation predicates, including for a 422. Unknown counts are null. A binding exception records the available numeric provider status and code. Receipts exclude prompts, response content and tool arguments. Reservations made before this feature have no receipt.

The offline native test runs the real parent, sandboxed child, tools, WebSocket client and SQLite storage. A local provider fixture reads, edits and pushes the model. The client logs tool events and checks the accepted Demand equation changes from 3 to 5, regardless of the sequence chosen. The test restarts the application and workerd, reopens the edited project and reads back a rejected inference receipt. The image test runs REST inside Docker with networking disabled. Gemma's remote tool choices require a separate live run.

## Original engine inference — first increment (PR #79)

The second original SD-AI inference lane is independent of the agent chat/tool-call lane. With the runtime and AI grant already enabled, an additional operator-controlled `ENGINE_INFERENCE_ENABLED=true` is required. Restart the container after changing it; the Durable Object checks the flag at every engine request. The default template leaves this disabled. No remote workflow or paid run is authorized by this PR.

The existing application preload configures the original LLMWrapper build/non-build defaults to the historical virtual alias `cloudflare/glm-5.3-flash` and reuses `scripts/cloudflare/other-engine-transport.mjs` and the original quantitative IGC adapter. The actual SDK request goes to a separate, exact private intercept endpoint, never to OpenRouter or the historical GLM endpoint. The effective Workers AI binding target is the already selected Gemma model. No actual provider credential is placed in the container. The structured-output schema is passed as the original bare schema; no JSON or equation repair is performed. Gemma thinking is disabled consistently with the established agent binding. Unsupported seed/top_p options fail closed rather than being silently discarded.

This increment has a deliberately separate 8192-token ceiling for engine requests (bounded by the originally requested maximum, input still capped at 131072 bytes); the agent path remains at 2048. Each engine invocation uses the existing project-wide cumulative budget and expiry, and a durable hash of the effective engine request prevents an identical invocation from being submitted again within that project's existing ledger. This conservative rule also rejects intentional identical requests; it is not a result cache or a general-purpose persistent job system. Receipts record engine channel, format, request hash, token cap, observed consumption, model, finish reason and failed checks without storing prompt or output. HTTP success at the binding means transport acceptance, not general schema validity or engine correctness. Malformed JSON and incomplete responses are rejected before returning to the SDK. The SDK requires total_tokens; when absent it is derived from observed prompt and completion counts solely in the SDK envelope, not reported as a provider-observed total. The REST BYOK exception is disabled only when this operator-funded binding lane is enabled, so the original application authentication key remains required.

CI exercises the actual `app.js` original REST quantitative engine with its real LLMWrapper/OpenRouter SDK, exact original Zod schema, a controlled provider fixture, the shared Durable Object, and the existing PySD client. The intended functional assertion is Inventory 10→30 over days 0–4, without modifying the returned equations. The test also rejects unauthenticated BYOK and a duplicate engine request, and checks the engine receipt. Passing this test is **offline functional evidence**, not live structured-output compatibility. The native binding's structured-output contract and model generation quality are still unverified remotely. With the same engine flag, the existing bubblewrap launch preloads the engine transport and the cloudflare tool lane resolves to the virtual alias. Only the original generate_quantitative_model tool is added to the gateway ceiling (12/25 when enabled, 11/25 otherwise); upstream per-agent, mode and model-state gates remain authoritative. Offline CI starts Merlin with an empty SD-JSON, generates the model through the original engine tool, edits Demand from 5 to 6, runs PySD, checks Inventory [10,16,22,28,34], persists confirmed updates, restarts and reopens the project. This is a scripted-provider test, not evidence that real Gemma chooses those tools. Other generation and analysis tools remain pending. The generic transport does not establish parity for any other engine. No Buffalo Persistent work is included.
