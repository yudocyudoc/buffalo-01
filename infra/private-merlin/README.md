# Private Merlin and Arena IGC

The Arena client binds to the named `ArenaMerlin` entrypoint on `buffalo-merlin-private-bridge`. Its `submit` RPC persists a versioned SD-JSON and queues one task. Its `read` RPC retrieves state and results after disconnection, including after the grant expires. Each of the first two stages has a separate, fixed Durable Object identity and can claim one task. This initial integration admits the Buffalo dialysisClinic development model.

A task alarm calls the named private Router, which claims the container, registers the HTTP and HTTPS egress intercepts, starts the digest-pinned image with Internet disabled and verifies its identity. The bridge then upgrades through the Router and the container DO to the original WebSocketHandler. The origin compares every client frame with the one it expects before forwarding it. The original handler prewarms the worker, selects Merlin and services one chat.

- **R** expects native model sync, the original unregistered-provider error, normal worker exit, zero intercepted requests on HTTP/HTTPS and confirmed container destruction. Its receipt is `ORIGINAL_AGENT_PROCESS_BOUNDARY_PASS_NO_INFERENCE`.
- **I** requires a successful R receipt on the same code and image, its own live grant, and a Workers AI credential bound only to the Router as `MERLIN_AI_TOKEN`. The agent uses the native OpenAI-compatible loop. The origin supplies the pinned model in the fixed question because Buffalo's native sync note references the session file. The gateway removes all tools before sending a single text request and rejects tool calls on return. The receipt retains the native terminal event, rendered output, provider usage and cleanup. Treat rendered HTML as untrusted and review the answer against the submitted model. The experimental receipt reports completion independently of scientific accuracy.

## Preparation and operation

1. Run `node --test infra/private-merlin/private.test.mjs`. The PR workflow also exercises the original R socket and worker in an isolated Linux network namespace. This is offline evidence.
2. From the root with dependencies installed, run `node infra/buffalo-origin/generate-probe-model.mjs` to produce the versioned SD-JSON used by the Arena client. Use the unedited file.
3. For an authorized deployment, build `infra/private-merlin/Dockerfile` with a digest-pinned Debian Node 22 base in `NODE_BASE_IMAGE` and the exact Git SHA in `BUFFALO_IMAGE_SOURCE_SHA`. Publish and independently resolve the remote digest. Supply that image reference in a copy of the adjacent Router config. Both Worker configs start disabled, without public routes or Cron.
4. An operator grants one task by setting the same serialized `MERLIN_GRANT` in the private Bridge and Router configs. It contains `project_id=arena-igc`, a UUIDv4 `task_id`, `phase` (R or I), `source_commit`, `image_digest` (sha256-prefixed digest), `model_sha256` and `expires` (epoch milliseconds within the next 22 minutes). I also requires explicitly approved `provider_model`, `max_posts=1`, `max_input_bytes` on the serialized provider request and `max_output_tokens`. The latter two are request limits. An account-wide currency cap is outside this grant. Use the Arena submit/read commands in the paired igc-modular adapter.
5. Read the terminal receipt by task ID. Restore both grants to `null`, remove the I-only secret if provisioned, and verify the container instance has stopped. R and I do not need D1 migrations. A failed or ambiguous POST remains spent and its usage can remain unknown. The watchdog cleans up abandoned containers without rerunning the model.

Source of the container network boundary and intercept behavior: [Cloudflare Durable Object Container API](https://developers.cloudflare.com/containers/api/durable-object-container/).
