# Buffalo Full — candidate LTM backend admission

This is a separate offline scientific experiment, based on merged #88 while #89's general upstream CI is being rerun. It does not replace PySD, enable a new engine, install a dependency in the production image, consume AI credits, change an original evaluator or change Cloudflare isolation. It can be integrated with the Seldon delivery branch after that branch is approved. SD-AI's own `get_feedback_information` tool requests LTM evidence from the client; its PySD wrapper supplies trajectories rather than LTM. The separate original experimental Simlin agent uses a nested Docker/Claude path, not a ready-to-use deterministic analysis service. Use the published Python API directly in the isolated candidate, not the experimental agent.

## Selected candidate and sources

- `pysimlin==0.8.5`, import `simlin`. [Pinned release](https://pypi.org/project/pysimlin/0.8.5/); [tagged Python API](https://github.com/bpowers/simlin/tree/pysimlin-v0.8.5/src/pysimlin); [tagged corrected flow-score regression](https://github.com/bpowers/simlin/blob/pysimlin-v0.8.5/src/simlin-engine/tests/integration/ltm_flow_to_stock.rs).
- [Schoenberg, Hayward & Eberlein, 2023, Improving Loops that Matter](https://doi.org/10.1002/sdr.1728), equations 2–3 and tables 2–3. Corrected flow-to-stock score uses changes in flows, not their levels.
- [Pinned original Bass reference](../BASS_FEEDBACK_REFERENCE.md), already validated in #88. The source JSON supplies relative loop percentages, not stock trajectories or original run receipt.

## Criteria fixed before first execution

1. Published flow aggregation example: inflow steps 5→10 and outflow 4→5 at t=2, Euler dt=1, stock initially 100. Exercise the two model representations through the actual Simlin backend. Use RAW link scores, not per-target normalized link scores. Direct inflow score +1.25 and outflow −0.25 at the step; other steps zero. In the equivalent aggregated model, inflow→net and outflow→net must have the same scores; their products with net→stock must equal the direct links. Absolute tolerance 1e-9. Both computed stock trajectories must equal the Euler recurrence [100,101,102,107,112,117] over t=0..5. The paper labels stock changes at the interval's end; the tagged Simlin test scores the flow change at the current sample t=2. The 0*s terms close inert feedback paths as in the tagged upstream regression; they do not change trajectories.
2. Independent two-loop births/deaths control: a=100 initially, births=.1*a and deaths=a/20. Euler dt=1, 0..10. Exhaustive same-partition signed shares +2/3 and −1/3 after t=0; both zero initially. Absolute score tolerance 1e-9. Check stock series against 100*(1.05)^t.
3. Original Bass XMILE file, unedited. Exact 241 samples, time 0..15 step 1/16. Match precisely two loops by directed cycle (rotation allowed; reversal not allowed), with opposite runtime polarities in one non-null partition. Preserve signed relative shares. Check zero initial scores, absolute shares summing to one thereafter (1e-9), exact first balancing-majority sample 9.625 and no subsequent transition back; compare **all** 482 score magnitudes, converting fractions to percent. Provisional engineering admission threshold 0.1 percentage points max absolute difference from upstream Stella-labelled fixture. This tolerance is a decision for this bounded experiment, not a published Stella-equivalence standard, and will not be relaxed post hoc to obtain green. Separately check both stocks and adoption flow against independent Euler recurrence from the original equations (atol 1e-6, rtol 1e-10); record complete measured series. Do not compare those trajectories to nonexistent Stella trajectory evidence.

The runner prints a JSON report with dependency versions, exact input hashes, individual checks, trajectories, signed backend scores, backend loop identifiers and partitions, numerical errors and observed periods. CANDIDATE_PASS is required for this candidate's CI to pass. NUMERICAL_MISMATCH or EXECUTION_FAILURE is retained as evidence, not repaired or silently aligned. No interpolation, one-step shifting or renaming polarity to match the reference. At this stage the version is pinned, transitive resolved versions and image ID are recorded rather than locked; a release build will need a reproducible wheel/dependency lock. The build downloads public wheels; execution runs unprivileged in a read-only container without networking or secrets. No production adoption before reviewing the evidence.
